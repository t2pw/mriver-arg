## 1. 進行検証の結果（機械的に確定した事実）

完走は可能。全35ページ到達、詰みなし。キーワードは謎解き答え2件を除き、すべて到達時点の可視テキストに存在する。その上で以下が確定。

### 1-1. 「月湯温泉」1検索で手記①②が同時解放【バグ】
kiroku_001 と kiroku_002 が同じキーワードを持つため、`submitKeyword` のループ内で
kiroku_001 が解放された直後に kiroku_002 の prereq が満たされ、**1回の検索で両方開く**。
手記①を読む前に②が開いており、読書順が壊れる。
→ 対処：kiroku_002 のキーワードを変更（例：手記①末尾の固有語）するか、kiroku_002 を prereq 自動解放に変更。
※ os.js の keywords 配列は手動管理のため、変更値の決定は制作者。

### 1-2. 第2層が7ページ一括解放【ペーシング崩壊】
`checkPrereqUnlocks` は「prereq が**解放済み**」で連鎖するため、inochi 解放後の最初の
ページ表示で voices → tegami → sns → momo → loop → data_trace → **receiver_lock** まで
全部いっぺんに開く。hub_002 の本文は「一つ読めば次が自動で開く」と宣言しているが、
実際は一括投下で、通知も束で届く。第3層の入口（receiver_lock）まで先に見えてしまう。
→ 対処：連鎖条件を「prereq が**閲覧済み**（koe_history に存在）」に変更。
`_loadPage` は既に `addHistory` を呼んでいるので、os.js 側の条件を1箇所変えれば成立する。

### 1-3. エンディングが選択前に全解放【演出崩壊】
hidden 解放の連鎖で fumi_tegami / choice / **wiki_add / wiki_skip / epilogue** が同時に開く。
「追記しますか」の選択を提示する前に、「追記しない選択」「エピローグ（GAME CLEAR）」が
解放済みとしてファイル一覧・通知に並ぶ。選択の重みが消える。
→ 対処：wiki_add / wiki_skip / epilogue は prereq 連鎖から外し、choice ページ内の
ボタン押下で `markRestored` する（選択そのものを解放トリガーにする）。

### 1-4. 最終謎の答えが序盤に露出【謎解き無効化】
hidden の解錠キーワード「あなたはここにいた」が **photo_001 の裏面メモ**（スポークB最初の
ページ）にそのまま書かれている。最終モールス解読の答えを序盤から知っている状態になる上、
序盤に検索すると prereq 未達で**完全無反応**＝バグにしか見えない。
→ 対処：photo_001 の裏面メモを設計書どおり「**この人はここにいた**」へ変更。
モチーフの反復は保ちつつ、最終解読で「あの写真の言葉が"あなた"に変わって返ってくる」
という着地に強化される。fumi_tegami（hidden 後）での全文一致は問題なし。

### 1-5. 「正しいが今は開かない」キーワードが完全無反応【詰み体感の主因】
prereq 未達のキーワードを検索しても、ハズレ入力と同じ無反応。検証で10件確認
（月湯温泉/猫塚清治/清治/昭和24年/M川駅/蒼沼ブルーランド 等は prereq 未達時点で本文に
出現済み）。プレイヤーには「キーワードが間違っている」と区別できない。
→ 対処：`submitKeyword` の戻り値に「一致したが前提不足」の状態を追加し、UI で
「── 照合一致。ただし参照元の記録が不足しています」のように返す。完全一致仕様は維持。

### 1-6. その他
- `pages/soran_profile.js` は PAGES 未登録のままロードだけされている（統合済みの遺物）。削除推奨。
- `pages/soran_intro.js` も PAGES 外（メッセージスレッドとして動作中なので現状OK、登録不要の旨をコメントに残す）。

## 4. シナリオ根本診断

通読した上での結論：**文章は書けているが、構造が「museum tour」になっている。**
枠物語（index.html の拾得記事）と最終盤（fumi_tegami 以降）は強い。問題は中間の25ページ。

### 4-1. 最大の問題：archive_about が全部の謎を最初に答えてしまう
1ページ目で「私は現代から来た／1949-08-16 の夜に清治に救われた／月湯で24年／
清治は記録にない／記録してほしい」まで全て明かす。以降の25ページは**既知の事実の
詳細化**であり、プレイヤーが追う問いが存在しない。読む動機が「次のキーワードを
探すため」しかなくなり、それが「作業感」の正体。

→ **再構成案：archive_about を「問いの提示」に書き換える。**
明かすのは「戸籍のない記録者がいた／このアーカイブを残した／封鎖されている」まで。
以下を中盤の発見に移す：
- 「小蘭は現代人だった」→ 手記の黒塗り現代語・「クラウド」・月湯の既視感から
  **プレイヤーが自力で気づく**（中盤のアハ体験その1。3-の黒塗り復元パズルと連動）
- 「清治が記録から消えている」→ bbs/photo の照合で確定する事実に
- 「記録してください」の依頼 → choice まで温存（現状 choice の依頼が初出の方が刺さる）

### 4-2. 受信者の正体バラし
index.html の追記が「これは私が読むためのものではない。あなたのものだ」と
**hidden の核心をそのまま予告**している。ここは「受信者欄が読めない」で止め、
深沢にも分からないままにする。

### 4-3. 現在時制の脅威・変化がない
全事件が50年前に完結しており、プレイヤーの行為で動くものが最後の wiki 編集まで無い。
不明送信元のメッセージ4通も進捗通知にとどまる。
→ 安価で効く追加：**タコ（機械）の劣化を時間圧にする**。メッセージに
「記録セクタの破損が進行しています」等を混ぜ、進むほど文字化けが増える／
読み終えたページが一瞬ノイズ混じりで再表示される等。「あなたが読むことが
記録の救出である」というコアコンセプトをゲーム内の手応えに変換する。

### 4-4. 中盤に疑念→反転がない
全ページが小蘭の主張をそのまま裏書きする一本道。
→ 反転候補（低コスト）：**「清治は実在したのか」をプレイヤーに疑わせる**。
材料は既にある——写真の出所は老婆の伝聞、名簿の蛸川██は身元不明、清治の記録は
一切ない、語り手は戸籍のない自称時間漂流者。第2層で「全ての証拠が小蘭一人に
遡る」ことを一度突きつけ（例：inochi の「目撃者不在」を自分への疑いに反転させる）、
hidden〜fumi_tegami で確信に変える。そうすると最後の wiki 追記が
「信じることを選ぶ」行為になり、choice の重みが跳ね上がる。

### 4-5. 反復の刈り込み
「あなたはここにいた」「清治さんの名前はそこになかった」「記録から消えた」が
15ページ近くで再説明される。各フレーズの使用箇所を1〜2箇所の最良の位置に絞る
（特に「あなたはここにいた」は 1-4 対応後、fumi_tegami をほぼ初出にする）。
第2層の inochi / voices / sns は論説調が続くため、sns は momo と統合候補。
