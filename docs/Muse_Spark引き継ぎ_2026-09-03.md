# 「声は壁を透して」Muse Spark 実装引き継ぎ

作成日：2026年9月3日

対象：次期UI・ゲーム進行・謎解きの再構築

基準となる現行版：commit `4ac53ff` / https://mriver-arg.pages.dev/

## 0. この文書の位置づけ

この文書は、2026年9月3日の制作者テスト後に決まった**次期改修の引き継ぎ**である。
現行実装の説明は `引き継ぎメモ_v16.md` と `docs/再設計書_2026-09-02.md` にあるが、
UI、進行案内、謎解き、導入人物については本書を優先する。

今回は既存画面への小改修ではなく、物語本文と素材を再利用した**体験層の再構築**として扱う。
現行本番は動作しているため、完成前に `prod` へ反映しないこと。

## 1. テストで判明した問題

制作者本人が約47%までプレイした時点で、次の問題を感じた。

- 見たページと、まだ見ていないページを判別しづらい。
- 次に何から手を付ければよいか分からない。
- キーワードで開きそうでも、どこへ入力するのか分からない。
- そもそも何をするゲームなのか、導入から理解しづらい。
- スマートフォン風UIやPrayストアは、見た目の着想が先で物語上の必然が弱い。
- モールス符号と16進数の変換は作業感が強く、謎としてあまり面白くない。

この改修の最優先目標は、難易度を下げることだけではない。
**プレイヤーが「今していること」と「次にできること」を理解しながら、観察と推理を楽しめるようにすること**である。

## 2. 制作者が確定した方針

以下は提案ではなく、実装の前提として扱う。

1. 既存セーブデータの移行は不要。
2. 現在のスマートフォン風UIにこだわらない。全面的な再設計可。
3. 現在のモールス符号・16進数の謎にこだわらない。廃止・置換可。
4. Prayストアにこだわらない。役割ごと置き換えてよい。
5. 発見されたタコは、ぬいぐるみに機械を入れたものではなく、**タコそのものがコンピューター**である。
6. 発見者の技術者が、保護した実機へ外部から接続する仕組みを作った。
7. 接続後に動くのは発見者が作った画面ではなく、**蛸川小蘭が自作したOS**である。
8. 発見者の名前は **渡利直哉（わたり・なおや）** とする。

「渡利」は福島市の実在地区名にちなむ。ゲーム内で由来を説明する必要はない。

## 3. 新しい体験の核

プレイヤーの立場を次の一文で統一する。

> 渡利直哉が公開した隔離接続を通じて、発見されたタコ型コンピューターに入り、蛸川小蘭のOS上で欠けた記録を調べる。

ゲーム開始後、30秒以内に次の三点が分かること。

- 目的：欠けた記録を読み、誰の存在を残そうとしているのか調べる。
- 基本操作：新着資料を読む、資料同士を比べる、必要な外部記録を開く。
- 当面の行動：画面に表示された「次の復元」を一つ実行する。

説明文の候補：

> この端末には、欠けた記録が残されています。
>
> 新しく復元された資料を読み、外部の記録と照らし合わせ、受信先を復元してください。

これはプレイヤー向けの操作説明であり、物語の真相は説明しすぎない。

## 4. 入口を三層に分ける

### 4.1 渡利直哉の技術記録

`index.html` は発見経緯を伝える入口として残す。ただしnoteの模倣ではなく、
渡利個人の簡素な技術記録サイトにする。

- 著者名：渡利直哉
- 記事案：「解体現場で回収した布製端末を、読み取り専用で公開する」
- 記載内容：発見場所、外観、端子、起動時刻、隔離した理由、公開できる範囲。
- 技術説明は短くし、OSや小蘭の正体を渡利に断定させない。
- CTA：「隔離セッションを開始」

記事は発見報告であり、記事画面そのものを操作端末にしない。

### 4.2 渡利のリモートブリッジ

新規画面 `remote.html` を想定する。現代側の中継画面であり、小蘭OSとは明確に別デザインにする。

表示例：

```text
WATARI REMOTE NODE
TARGET  : T-08
LINK    : STABLE
MODE    : READ ONLY
INPUT   : RELAY ENABLED

[ CONNECT ]
```

公開しているのは実機の無制限な直接操作ではなく、隔離された読み取り用セッションとする。
映像と入力を中継しているだけで、渡利がOSを復元・制作したようには見せない。

### 4.3 蛸川小蘭のOS

接続後に小蘭の署名または起動ログが現れ、独自OSが立ち上がる。
現行の `phone_shell.html` はURL互換のため残してよいが、見た目と意味はスマートフォンから小蘭OSへ変更する。

画面遷移：

```text
渡利の記事 → 隔離接続ゲート → 小蘭OSのブート → 初回復元案内 → 探索
```

三画面の見た目を混ぜない。

- 渡利の記事：明るい、現代的、写真と実測値。
- リモートブリッジ：暗い、無彩色、通信状態のみ。
- 小蘭OS：独自の色・動き・文字組み。作品の中心となる画面。

## 5. 小蘭OSの推奨ビジュアル

OSは既存スマホのホーム画面を模倣しない。タコ型コンピューターの構造を操作体系に使う。

### 中心画面

- 中央に「記録核」。現在の目的と復元状態を表示する。
- 周囲に八本の記録肢。各肢が資料群へつながる。
- 吸盤はファイルまたは断片を表すが、装飾ではなく状態表示として使う。
- 新しい資料が開くと、その肢を光が走って吸盤が点灯する。
- 破損箇所はノイズ、欠け、途切れた線で示す。

### 必須の状態表現

色だけに頼らず、形と文字でも区別する。

| 状態 | 表示 |
|---|---|
| 未発見 | 輪郭のみ／名称なし |
| 復元済み・未読 | 強い脈動＋「新規」 |
| 読了 | 安定点灯＋チェック＋読了日時 |
| 再確認推奨 | 小さな接続線＋「関連資料あり」 |
| 外部照合待ち | 開いた端子＋必要な外部資料名 |

常に画面上部または記録核に「次の復元」を一件だけ大きく表示する。
複数の任意行動はその下に分け、必須行動と混在させない。

表示例：

```text
次の復元
「昭和二十四年八月の写真」を確認する

進行　第一記録群  3/5
未読  1　　関連資料 2
```

全体のパーセントだけを主案内にしない。幕・件数・未読数を併記する。

## 6. 基本ゲームループ

一回の進行を次の短い循環にする。

1. 記録核で「次の復元」を見る。
2. 点灯している未読資料を開く。
3. 写真、地図、名簿、手紙などから一つの違和感を見つける。
4. 必要なら二資料を並べ、箇所を選ぶ・重ねる・関係線をつなぐ。
5. OSが照合結果を返し、次の記録肢を復元する。

汎用のキーワード入力欄は廃止する。
文字入力が必要な場合は、その資料内に目的を明示した専用欄を置く。
「何を」「なぜ」入力する欄なのか分からない状態を作らない。

## 7. 謎解きの再設計

### 廃止するもの

- モールス符号を別ツールへ転記する必須工程。
- 数字列を16進変換器へ転記する必須工程。
- 本文中の単語を推測して汎用欄へ入力する解錠。
- Prayストアで変換アプリを探し、導入する必須進行。

`tools/morse.js`、`tools/hexconv.js`、`pray-store/` は旧版参照として残してもよいが、
新進行からは外す。削除は新構造の完成確認後に行う。

### 推奨する謎

1. **写真の観察**

   修復スライダーや拡大で新聞の日付、服装、壁面の文字を見つける。正解語の入力ではなく、該当箇所を選択する。

2. **地図の重ね合わせ**

   1949年、1954年、1973年の書き込みをドラッグで重ねる。共通する目印から蒼沼への経路が浮かぶ。

3. **名簿と手記の比較**

   二つの資料を左右に置き、同じ日付・筆跡・欠けた名前を線で結ぶ。公的記録から抜けた人物をプレイヤー自身が確認する。

4. **時系列の復元**

   写真、切符、手紙、保存ログを順番に並べ、小蘭が24年間何をしていたかを組み立てる。

5. **受信者の関係図**

   終盤は暗号変換ではなく、「記録した人」「残された人」「受け取る人」のカードを関係図へ配置する。最後の空欄が現在の閲覧者を指す。

難しさは暗号知識ではなく、資料間の食い違いに気づくことから生む。
各謎には二段階ヒントを用意する。

- ヒント1：見るべき資料を示す。
- ヒント2：見るべき位置または操作を示す。

ヒント利用によるペナルティや結末差は付けない。

## 8. Prayストアの扱い

Prayストアは新しい体験の中心から外す。
小蘭が現代の技術者で、このOSの作者である証拠だけは別の形で残す。

第一候補は、小蘭OSのブート署名と、外部に残った簡素な開発記録の組み合わせである。

```text
KORAN SYSTEM / build 08.16
author: 蛸川小蘭
storage topology: 8-arm distributed archive
```

外部記録はストアの模倣ではなく、個人の開発ログ、ソフトウェア目録、キャッシュされた作者ページなどにできる。
第三者記録としての役割が不要になった場合は、外部ページ自体をなくしてよい。

## 9. 物語で維持するもの

UIを変えても、次の物語上の核は維持する。

- 作品名は「声は壁を透して」。
- 主人公的記録者は蛸川小蘭。
- 小蘭は現代の技術者で、1949年に移動し、1973年まで記録した。
- 猫塚清治は公的記録から抜け落ちた人物。
- 清治さんの写真は存在しない。
- 現在の人物写真は記録者自身だが、本文では断定しない。
- タコ型コンピューターは小蘭の記録媒体であり、八本の肢へ記録を分散している。
- 1973年以後の現在情報は、タコ自身の現地観測ではなく外部接続による。
- 終盤でプレイヤーは、記録へ一行を残すか、現実の記録を調べに戻るかを選ぶ。
- 二つの選択に正解・不正解、優劣、達成率差を付けない。
- `おかえり` に対する任意返信は残してよいが、上位エンド扱いしない。
- 不明送信元の正体と、境界の仕組みを説明しない。
- 可視本文では「世界線」、実在事件名、ジャンル名を使わない。免責表示は例外。

現行資料の内容整理は `docs/再設計書_2026-09-02.md`、文体は
`docs/文体設計書_2026-09-02.md` を参照する。

## 10. 現在の実装から再利用できるもの

- `images/`：写真、地図、OGP画像。
- `pages/`：15資料へ統合済みの本文。DOMをそのまま移す必要はない。
- `fushima-archive/`：外部の事件資料・図書館資料。
- `blue-land/`：蒼沼ブルーランド保存会。
- `m-kawa-wiki/`：終幕の外部追記画面。
- `CREDITS.md`：画像出典。
- `docs/文体設計書_2026-09-02.md`：発信元別の文体規則。
- `docs/再設計書_2026-09-02.md`：15資料の情報担当とネタバレ順。

現行コードの注意点：

- `dist/` は生成物。直接編集しない。
- `build_dist.js` は公開ファイルのホワイトリストを持つため、新規 `remote.html` 等を追加したら更新する。
- `extract_scenario.js` と `check_progression.js` は現行構造前提。新しい資料IDと進行へ合わせて更新する。
- 外部サイトの訪問状態は現在 `koe_external_visits` に保存される。
- 新版は既存セーブ移行不要。古いキーとの対応表は作らなくてよい。
- ただし通常プレイで保存状態を初期化する処理は入れない。新版専用のキー名を使い、テスト用リセットだけを用意する。

## 11. 推奨する実装順

### Phase A：画面骨格

1. `index.html` の深沢表記を渡利直哉へ変更し、技術記録として再編集。
2. `remote.html` を追加。
3. `phone_shell.html` を小蘭OSの最小プロトタイプへ置換。
4. 記録核、八本の肢、未発見／未読／読了の三状態を実装。

この時点では全文や謎を移さず、ダミー資料3件で操作感を確認する。

### Phase B：案内と進行

1. 初回目的表示。
2. 常設の「次の復元」。
3. 読了・未読・外部照合待ちの状態管理。
4. 第一幕だけを実資料で通せるようにする。

### Phase C：謎の置換

1. 写真観察。
2. 地図重ね合わせ。
3. 名簿・手記比較。
4. 時系列復元。
5. 受信者関係図。

モールス・16進・Prayストアを進行から外すのは、代替導線が完成してから行う。

### Phase D：全編移植と終幕

1. 既存15資料の情報を新しい流れへ配置。
2. 外部3サイトとの往復をOS内のタスク表示へ反映。
3. 二つの終幕と任意返信を接続。
4. シナリオ抽出と進行検証を更新。

### Phase E：公開前確認

1. 390×844とデスクトップで全編を通す。
2. 初見の人が説明なしで最初の資料へ進めるか確認。
3. 途中再開時に、未読と次の行動が一画面で分かるか確認。
4. 両方の終幕を確認。
5. `node build_dist.js` の生成物だけを公開対象にする。

## 12. 受入基準

- 初回接続から30秒以内に目的と最初の操作が分かる。
- どの画面でも、未読資料と次の必須行動へ二操作以内で到達できる。
- 見た資料／未読資料／未発見資料が色以外でも区別できる。
- 進行に必要な入力欄が、対象資料と離れた場所に存在しない。
- 汎用キーワード欄を使わない。
- モールス符号と16進数を知らなくても完走できる。
- Prayストアを訪問しなくても完走できる。
- 渡利の画面と小蘭OSを見間違えない。
- 小蘭がOS作者で、渡利は接続手段の作者だと自然に理解できる。
- 既存セーブがなくても最初から完走できる。
- 片方の終幕だけが正解に見える表示をしない。
- スマートフォンとデスクトップの双方で、横スクロールや操作不能がない。
