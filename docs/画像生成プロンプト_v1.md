# 画像生成プロンプト v1（2026-06-10）

外部の画像生成AI（Midjourney / DALL-E / Stable Diffusion 等）に渡すためのプロンプト集。
対象は引き継ぎメモ_v16 §6 バックログの承認済み4件。`docs/画像仕様書_v1.md` の共通方針に準拠。

## 共通仕様（全画像）

- 配置場所：`images/`。推奨サイズ：**横幅1200px前後**（アスペクト比は各画像の指定）。形式：写真調はJPG。
- アーカイブ収録画像（①②④）のトーン：**セピア〜モノクロ、古い記録・スキャン風**（1949〜1963年の遺物を2026年にスキャンした体）。
- ③（タコ）のみ例外：深沢のブログ（2026年）掲載の**現代のスマホ写真風・カラー**。
- **答えを文字で書かない**：①の「0816」を数字として描かない。穴の配置のみ。
- スマホ画面（横幅390px想定）で拡大せずに記号・文字が判別できるコントラストにする。

## 生成AI利用上の注意（重要）

- **日本語の文字の描画は現状のAIでは高確率で崩れる。** ②（M川事件）・④（駅名標・新聞）の文字部分は、
  「文字なしで生成 → 文字だけ後から画像編集で合成」が最も確実。プロンプトには文字指定を含めてあるが、
  生成物の文字が崩れていたら迷わず後合成に切り替えること。
- **①の穴の数・並びは厳密に指定どおりである必要がある**（パズルの正答に直結）。
  生成AIは個数を正確に守れないため、①は「穴のない障子写真を生成 → 穴を画像編集で開ける」を推奨ルートとする。
- 生成後チェックリストを各画像に付けた。納品前に必ず確認。

## 差し替え時の手順（共通）

1. 生成画像を上記チェックリストで確認（特に①の穴パターンと文字の判読性）。
2. `images/` の既存ファイルを置き換え（ファイル名は変更しない。コード側の修正不要）。
3. ④を実施する場合のみ、photo_002/photo_003 の本文・キャプションからのキーワード削除（改善計画 §3）と
   `node extract_scenario.js` → `node check_progression.js` の検証が必要。①②③は画像差し替えのみで完結。
