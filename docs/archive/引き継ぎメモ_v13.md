## 1. プロジェクト概要
- 作品名「声は壁を透して」。松川事件をモチーフにした**フィクションのARG**（代替現実ゲーム）。
- GitHub Pages でホスティングする**静的サイト**。ビルド工程なし（素のHTML/JS）。
- 入口 `index.html`（発見者note風の導入ページ）→ `phone_shell.html`（スマホ風SPA本体）。
- 体験：拾われた古い端末のアーカイブを、プレイヤーがブラウザで読み解く。手記・写真・掲示板・地図・電文の5スポークを集め、第2層・第3層へ。

## 2. アーキテクチャ / 重要な実装規約

```
index.html            発見者「深沢」のnote風導入ページ → phone_shell.html へフェード遷移
phone_shell.html      メインSPA。Shell（UI）と KoeOS（os.js）で構成
os.js                 KoeOS：PAGES定義・キーワード認証・解放ロジック
pages/*.js            各ページの本文（PAGE_CONTENT[id] = () => `...html...`）
tools/*.js            解析アプリUI（TOOL_UI[id]）。hexconv / morse の2つ
extract_scenario.js   node実行でscenario_text.txt生成（導入+全ページ+小蘭メッセージ）
scenario_text.txt     生成物。ページ等を編集したら `node extract_scenario.js` で再生成
images/               画像。photo_*.jpg, map_fushima.jpg, puzzle_*.jpg 等
```

### 解放ロジック（os.js）
- `PAGES` 各要素：`{ id, title, locked, keywords:[], prereqs:[], phase, spokeGroup, icon }`
- **キーワード認証は完全一致**（`submitKeyword`内 `return norm === nk;`。空白は除去して比較）。
  - ※以前は部分一致だったが「M川」で複数開く問題のため完全一致に変更済み。表記ゆれは keywords 配列に列挙する方針。
- `checkPrereqUnlocks()`：keywords が空で prereqs を全て満たすページを連鎖的に自動解放（第2層・第3層の自動送り）。
- `_checkHub()`：A〜E全スポーク完了で `hub_002` を自動解放。
- 第2層（inochi→voices→tegami→sns→momo→loop→data_trace）と第3層の各ページ末尾に「次へ」誘導ボタンあり。inochi のみキーワード解放、以降は prereq 自動解放。

### キーワード配列の扱い
- **原則ユーザー手動管理**だが、フィードバック対応での変更はユーザー指示済みなら可。変更時は本人確認が無難。
- メッセージUI：`STORY_MSGS`（phone_shell.html内）。gate指定ページの復元時にトースト配信。小蘭の私信は二人称で「あなた」に語る。
- メッセージ内ボタンからの遷移：`open()` 冒頭で `#msgview` を閉じる実装済み（押下時に遷移先が見える）。

### ナビ規約
- `Shell.bNavigate('id')` でブラウザ内ページ遷移。`Shell.open('appId')` でアプリ切替。
- 画像の onerror フォールバックは**ネストした引用符を避ける**こと（未生成画像でonerrorが発火しても壊れない書き方に。telegram_001.js 等を参照）。

### 文体・呼称の規約
- 小蘭の語りはすべて一人称。彼を指すときは「**清治さん**」。
- 「猫塚清治」は記録上の固有名詞のみ（名簿・宛先欄・封筒に名前を書く行為・Wiki項目・三人称の終幕台帳 epilogue/choice）。
- 年代：小蘭個人の期間は「24年」、消息は「1973年」。**裁判・運動の14年／無罪確定1963.9.12は史実なので据え置き**（voices / inochi / bbs_003）。

## 3. 謎解きの構造（重要）

### スポークE（電文）
- `telegram_001`：小蘭が月湯を去る前に**障子に穴をあけ、宿の主人へ電報で「写真を撮って残して」と依頼**したエピソード。2つの生データ画像を提示。
  - 第1段 `images/puzzle_e_hex.jpg`（16進 `53 55 4A`）→ **16進変換器** → 「ショウジ」＝障子（どこを見るかのポインタ）
  - 第2段 `images/puzzle_e_shoji.jpg`（障子の穴4升）→ **モールス読取機** → `0816`
- `telegram_002`：`0816 = 八月十六日 = 事件の夜＝全ての始まり`。**その日付をアーカイブの鍵（N-0816）にした**、という意味づけ。

### 第3層ゲート（受信者ロック）※v13後に改修
- `data_trace` →「最後のロックへ」→ `receiver_lock` →（謎解き）→ `hidden`。
- **既存ツールのみの2段チェーン**：
  1. `receiver_lock` 画面内で、文字化けした不明送信元からモールス18符号が届く（画像は使わない）→ **モールス読取機** → `412116261010224216`
  2. それを16進ペアに区切る `41 21 16 26 10 10 22 42 16` → **16進変換器** → **アナタハココニイタ**
  3. ブラウザに「あなたはここにいた」または「アナタハココニイタ」を入力 → `hidden` 解放
- hexconv 対応表に追加済み：`10コ 16タ 21ナ 22ニ 26ハ`（既存 `41ア 42イ` ほか）。
- **新規ツールは作らない方針**（hexconv / morse のみ）。
- 送信元はタコのぬいぐるみ内の機械/AIを示唆するが、名前や正体は最後まで明かさない。小蘭から直接メッセージが届く演出にはしない。

## 5. 作業フロー / 注意
- ページや導入・メッセージを編集したら **`node extract_scenario.js`** で `scenario_text.txt` を再生成。
- コミットは機能単位で。`シナリオ改善案_*.txt` や `テストプレイフィードバック*.txt` はユーザーのメモなので**コミットに含めない**運用（`git reset -- *.txt` 等で除外してきた）。
- Windows環境のため改行コードは CRLF 警告が出るが無害。
- ビルド不要。ブラウザで `index.html` を開けば動作確認できる（GitHub Pages 公開）。
